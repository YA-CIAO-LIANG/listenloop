# M2.5 魚缸激勵系統

## Context

M2 已經完成，七天循環可以完整走完。M2.5 要加上「看得見的獎勵」，讓學習者每天想回來練習：

- 練習得到**點數**，點數只能用來在商店買魚；
- 每天完成任務得到 **1 份飼料**（和點數分開計算）；
- 在首頁點魚缸水面撒飼料**餵魚**；
- 首頁日曆的魚飼料圖示代表**那天有餵魚**；
- 魚會有溫和的飢餓狀態，也可以和牠們互動；
- 買到的魚會游在首頁背景的**寫實像素風魚缸**裡。

整個系統只用點數，不涉及真錢：沒有內購、沒有付費點數，也沒有任何金流。

已經確認的決定：

- 魚缸是**整個首頁的固定背景**；
- 魚、魚缸背景、飼料都是像素風，由程式用 Canvas 2D 繪製（2026-10-27 改方向，取代原本的 Sketchfab 3D 模型加 Three.js）；魚的風格是**「寫實配色＋大眼萌系」**，規則見第 1a 節，所有魚種都照這套規則畫。

規則的數字都集中在 `lib/rewards.ts` 的 `REWARDS`，修改時兩邊一起更新。

## 1. 像素風的做法（Canvas 2D，程式繪製）

**為什麼不用 3D**：3D 模型要登入第三方網站下載、處理授權與作者標示，縮圖還需要另外的瀏覽器算繪；程式繪製的像素畫沒有外部素材、不需要新套件，風格也能完全一致。

- **繪製**：`lib/pixel-fish/` 的純函式依每個魚種的參數算出每個像素的顏色，輸出 RGBA 陣列（不依賴瀏覽器，可以寫單元測試），元件再畫到 canvas。
  - 體型：以參數描述側面輪廓（每一欄身體的上緣與下緣）與各鰭的形狀。
  - 花紋與顏色貼近真實物種（例如小丑魚的白帶與黑邊、鯨鯊的斑點）；比例與眼睛依第 1a 節的萌系規則。
  - 光影：把身體視為橢圓柱算法線，光從左上方來，明暗量化成 5 階並少量抖色；外輪廓用同色系深色描邊（不用純黑）。
  - 基礎尺寸以小畫布繪製（小丑魚 96 × 60 像素），顯示時放大成整數倍並關閉影像平滑化，保持像素銳利。
  - 眼睛不畫在身體畫格裡，而是另外畫成一張小圖疊上去（`lib/pixel-fish/eyes.ts`）；換表情、看向不同方向都不用重算整條魚。
- **動畫**：尾巴 2～4 格擺動、身體由頭到尾的正弦起伏、胸鰭拍動、轉身（橫向壓扁 → 翻面 → 展開）。所有畫格第一次使用時算好並快取，之後只做 `drawImage`。
- **魚缸背景與飼料**：同一套像素風格（水的深淺漸層、像素光斑、沙、水草、下沉的飼料顆粒）。
- **魚的顏色是插畫內容**，不使用設計系統的介面 tokens；每個魚種的色票放在 `lib/pixel-fish/species/`。

### 1a. 魚的風格規則：「寫實配色＋大眼萌系」（所有魚種都適用）

2026-10-27 確認（取代原本「不卡通化」的寫實比例）。之後每一種魚都照這套規則畫，樣板是 `/styleguide` 的小丑魚。

- **寫實的部分**：花紋、配色、光影維持真實物種的樣子（例如眼斑小丑魚的三條白帶與黑邊、鯨鯊的白色斑點與條紋）；光從左上方照下、5 階色階、同色系描邊，與第 1 節相同。
- **萌系的部分**：
  - **眼睛超大**：直徑約佔頭部（眼睛所在位置）高度的 1/3；深色虹膜，下半部帶一點暖色反光；大瞳孔。
  - **兩個白色反光點**：一個大的在上方、朝光源（左上），一個小的在對角（右下）。光源固定，魚轉身時反光點不跟著翻。
  - **身體稍微圓一點、短一點**：與大眼睛協調（小丑魚身高約為體長的 0.55，頭部比真實的更圓鈍）；鰭的形狀維持該物種的特徵。
- **表情動畫**：
  - **眨眼**：每隔 2～6 秒隨機眨一次，閉眼約 150 毫秒（眼皮是身體同色的皮膚加一道睫毛線）。
  - **看**：眼珠看向游標、手指或下沉中的飼料（飼料優先）；沒有目標時看前方。
  - **吃飽**：吃到飼料後約 2 秒，眼睛彎成開心的 ^ ^。
  - **飢餓**：眼皮半閉、眼珠往下；同時游得較慢、偏向缸底（第 2c 節）。
- **reduced motion**：不眨眼、眼珠不動，只保留靜態表情（例如飢餓時半閉、剛餵食時 ^ ^）。
- **預覽**：表情的觸發先在 `/styleguide` 用按鈕預覽（眨眼、撒飼料、表情「一般／吃飽／飢餓」），魚缸 PR 再接到真正的餵魚與飢餓狀態。

### 效能與無障礙守則（會寫進設計系統）

- 魚缸的程式只在首頁載入，其他頁面不受影響。
- 手機限制在 30fps，桌機 60fps；畫格切換約每秒 8 次。
- 魚缸最多同時顯示 12 隻魚。超過的魚一樣保存在「我的魚」，可以自己選要放哪幾隻進魚缸。
- 分頁被隱藏或切到背景時，暫停繪製。
- 系統開啟「減少動態效果」時，只畫一張靜止的畫面，魚不游動、不擺尾。
- canvas 加上 `aria-hidden`，純裝飾；魚缸裡有哪些魚改用文字列在「我的魚」。

### 整頁背景的可讀性

- 魚缸固定在首頁最底層（`position: fixed`）。
- 標題、點數、日曆、影片庫卡片都放在不透明的 surface 卡片上，文字對比沿用現有 tokens。
- 卡片之間留出空隙，讓魚缸透出來。
- 深色模式和淺色模式都用同一個水色調。

## 2. 點數與飼料（兩種分開計算）

### 2a. 點數：只用來買魚

數字集中在 `lib/rewards.ts` 的 `REWARDS`。

| 行為                                 | 點數                               | 說明                               |
| ------------------------------------ | ---------------------------------- | ---------------------------------- |
| 完成當天的**正式**任務（第 1～7 天） | +10                                | 每支影片、每週、每天只算一次       |
| 第 1 天、第 7 天聽寫的正確率加分     | + 正確率 × 10（四捨五入，0～10）   | 鼓勵認真聽寫                       |
| 跟讀平均涵蓋率 ≥ 90%                 | +5                                 | 「我念完了」完成的句子不算在平均裡 |
| 週結算通過                           | +50                                |                                    |
| 週結算沒通過，但完成了這一週         | +20                                | 不懲罰重來一週                     |
| 連續練習（以日曆日計算）             | 從連續第 3 天起，每天 +5（不遞增） | 只要當天完成任一個正式任務就算     |
| 重練                                 | 每支影片每天第一次重練完成 +2      | 鼓勵複習，但避免刷點數             |

- **防止重複領取**：每一筆點數都有唯一 ID，例如 `day:sintel:w1:d3`、`week:sintel:w1`、`streak:2026-10-27`。帳本裡已經有的 ID 不會再加一次，重新整理或重做都不會重複給點。
- **既有進度補發**：獎勵都從紀錄推算（正式進度、往週紀錄 `history`、練習紀錄 `ll-activity:v1`），帳本只發還沒領過的 ID，所以舊進度第一次開啟就會自動補發。已經重來一週的舊週，各天紀錄已清空，只能補發那一週的週結算點數。

### 2b. 飼料：每天完成任務得 1 份，用來餵魚

- **怎麼得到**：每個日曆日，第一次完成任一個**正式**任務時得到 1 份飼料。不論是哪支影片，一天最多 1 份；重練不算。
  - 唯一 ID 是 `feed:2026-10-27`，所以不會重複發。
- **可以累積**：飼料可以存起來，最多存 7 份，存滿後就不再增加。這樣偶爾沒空餵也不會白做。
  - 剛開始會送 1 份，讓第一次就能試著餵魚。
- **餵魚**：每撒一次飼料消耗 1 份。一天可以餵很多次，但日曆只記「這天有餵」。
- **既有進度補發**：已經完成任務的過去日子會補發飼料，但同樣受「最多存 7 份」限制。
- **日曆**：魚飼料圖示代表**那天有餵魚**，不是有練習。

### 2c. 飢餓狀態（溫和、不懲罰）

- 上次餵食之後，超過 1 天沒有餵，也就是今天和上次餵食日相差 2 天以上，魚就會進入「餓了」的狀態：
  - 游得比較慢；
  - 比較常待在缸底。
- 一餵食就立即恢復。
- **魚不會死亡、生病或消失**，也不會因為餓而扣點數。
- 首頁會用一行文字溫和地提示：「魚有點餓了，完成今天的任務就能得到飼料。」文字不只靠動畫傳達狀態。

### 商店價格

| 魚             | 價格 | 大約要練多久 |
| -------------- | ---- | ------------ |
| 小丑魚         | 40   | 約 2～3 天   |
| 水蝸牛         | 30   | 約 2 天      |
| 鯊魚（大白鯊） | 200  | 約一週半     |
| 鯨鯊           | 400  | 約三週       |

- **起始魚缸**：一開始就有一隻水蝸牛，讓魚缸不會是空的。
- 同一種魚可以重複購買。
- 點數只能用在商店，不能退款，也不會過期。

## 4. 資料與架構

### `lib/`

- **`lib/rewards.ts`**（PR a）：獎勵規則，全部是純函式。`REWARDS` 集中所有數字；`pointRewards`、`feedRewards` 從紀錄推算出帶唯一 ID 的獎勵；`streakPoints` 計算連續天數獎勵。
- **`lib/activity.ts`**（PR a）：每天的練習紀錄（正式任務、重練）。重練不寫進正式進度，所以另外記錄。
- **`lib/wallet.ts`**（PR a、b）：只新增不修改的帳本，點數（`earned`／`spent`）與飼料（`earned`／`used`）分開；PR b 加上擁有的魚與魚缸（最多 12 隻）、購買、見面禮水蝸牛。
- **`lib/claim-rewards.ts`**（PR a、b）：讀紀錄、領取、存檔；購買也走同一個佇列，不會互相覆蓋。
- **`lib/fish.ts`**（PR b）：魚的型別和驗證（`id`、`price`），資料放在 `data/fish/`，魚名與介紹在翻譯檔 `fish.<id>`。
- **`lib/pixel-fish/`**（像素魚）：繪製與動畫畫格的純函式，以及各魚種的參數與色票。
- **`lib/feeding.ts`**（PR c）：餵食（消耗飼料、記錄餵食日期）、`isHungry(lastFed, today)`，給魚缸和日曆使用。

### 儲存

- `lib/storage/reward-store.ts` 定義 `RewardStore`；MVP 用 localStorage（`local-reward-store.ts`），key 是 `ll-wallet:v1`、`ll-activity:v1`，之後可以換成 Supabase。

### 發點時機

- 正式任務、週結算、重練完成時，各頁存檔後順便呼叫 `claimRewards`。
- 因為有唯一 ID，就算呼叫很多次也只會給一次。

### 畫面

- **頁首**：顯示點數和飼料，整個徽章連到魚店。
- **首頁**：由上到下是標題卡、餵魚卡（剩幾份飼料、「餵魚」按鈕、飢餓提示）、這個月的日曆卡（有餵魚的日子顯示飼料圖示）、影片庫。
- **`/shop`**：每隻魚有像素畫縮圖（完成前先用佔位圖示）、價格、「購買」按鈕。點數不夠時按鈕停用，並說明「還差 N 點數」。
- **`/shop` 的「我的魚」**：可以選擇哪些魚放進魚缸。

## 5. 魚缸的餵魚與互動（PR c）

| 動作                       | 魚的反應                                                                             | 開啟「減少動態效果」時                               |
| -------------------------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| **點水面**（有飼料時）     | 從點的位置撒下飼料，飼料緩慢下沉；最近的幾隻魚游過去吃，吃完飼料就消失；記錄今天有餵 | 不播放下沉和游動，直接顯示「已餵食」，並記錄今天有餵 |
| 點水面（沒有飼料時）       | 不撒飼料，顯示「今天完成任務就能得到飼料」                                           | 同左                                                 |
| **點魚**                   | 轉身、吐泡泡，並在旁邊顯示名字（例如「小丑魚」）                                     | 只顯示名字                                           |
| **點玻璃附近**（畫面邊緣） | 附近的魚四散游開                                                                     | 不動                                                 |
| **游標或手指移動**         | 附近的魚好奇地慢慢靠近                                                               | 不動                                                 |

- **無障礙**：只靠點水面餵魚，鍵盤和螢幕閱讀器使用者會做不到。所以首頁的餵魚卡上也有一個「餵魚」按鈕，效果和點水面一樣，飼料從水面中央撒下。
- **點擊判斷**：以每隻魚目前的位置與外框判斷點到的是魚還是水面；畫面四邊的一定範圍算「玻璃附近」。
- **捲動和點擊**：魚缸是整頁背景，只有點在卡片之間的空白處才會觸發魚缸互動，點到卡片時一律照卡片本身的操作處理。

## 7. 已確認的決定（2026-10-27）

1. **像素風取代 3D**：不使用 Sketchfab 模型、Three.js 與縮圖算繪腳本；魚、魚缸、飼料都由程式用 Canvas 2D 繪製。
2. **風格「寫實配色＋大眼萌系」**：花紋、配色、光影寫實；眼睛超大（約頭高 1/3）、一大一小兩個反光點；身體稍圓稍短；會眨眼、看游標或飼料、吃飽 ^ ^、飢餓半閉眼；reduced motion 時只保留靜態表情（第 1a 節）。
3. **動畫**：尾巴 2～4 格擺動，加上身體起伏與轉身。
4. **水蝸牛**：寫實的殼與身體，沿著缸壁和缸底慢慢滑動。
5. **商店縮圖**：用同一套像素畫（靜態畫格）。
6. **先做小丑魚樣板**放在 `/styleguide`，確認風格後再做其他魚種。
7. **連續練習**：從連續第 3 天起，每天固定 +5，不遞增。
8. 不新增任何套件。

## 驗證（每個 PR）

- 本機跑五項檢查（lint、format:check、typecheck、test、build）。
- 用 production 模式確認：先確認埠沒有被佔用，結束後依埠號關閉伺服器。
- 開 PR，等 CI 通過後給你預覽網址，等你說「合併」才合併。
- 魚缸 PR 額外要做：
  - 用 Chrome DevTools 的效能錄製，確認手機模擬下維持 30fps；
  - 確認減少動態效果、分頁隱藏時會暫停。
