# M2.5 魚缸激勵系統

## Context

M2 已經完成，七天循環可以完整走完。M2.5 要加上「看得見的獎勵」，讓學習者每天想回來練習：

- 練習得到**點數**，點數只能用來在商店買魚；
- 每天完成任務得到 **1 份飼料**（和點數分開計算）；
- 在首頁點魚缸水面撒飼料**餵魚**；
- 首頁日曆的魚飼料圖示代表**那天有餵魚**；
- 魚會有溫和的飢餓狀態，也可以和牠們互動；
- 買到的魚會游在首頁背景的寫實 3D 魚缸裡。

整個系統只用點數，不涉及真錢：沒有內購、沒有付費點數，也沒有任何金流。

已經確認的決定：

- 魚缸是**整個首頁的固定背景**；
- 畫面走**寫實風、遊戲級模型**：每隻魚約 2～6 千面，有游泳動畫。

本文件是 M2.5 的設計與技術方案（2026-10-27 確認），實作分成三個 PR，見第 6 節。規則的數字都集中在 `lib/rewards.ts` 的 `REWARDS`，修改時兩邊一起更新。

## 1. 3D 做法比較

| 做法                            | 說明                                                                                                              | 優點                                                                                                                 | 缺點                                                             |
| ------------------------------- | ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| **A. Three.js（原生）** ✅ 推薦 | 用 client 元件包一個 `<canvas>`，只在首頁以 dynamic import 載入，用 `GLTFLoader` 和 `AnimationMixer` 播放游泳動畫 | 最輕：只多一個套件，gzip 後約 150～200KB，而且只有首頁會載入。可以完全控制效能（暫停、降低畫質、限制幀率）。MIT 授權 | 程式比宣告式寫法多一些，要自己寫游動路徑                         |
| B. React Three Fiber + drei     | 用 React 元件的寫法描述 3D 場景                                                                                   | 寫法和 React 一致，生態系豐富                                                                                        | 要多 3 個套件，bundle 比較大。魚缸只是背景，用不到它的優勢       |
| C. 預先算好的影片背景           | 在 Blender 算繪成循環影片                                                                                         | 執行時最省電，畫面可以最寫實                                                                                         | **買了魚也不會出現在魚缸裡**，背離「買魚」的核心體驗，所以不採用 |
| D. `<model-viewer>`             | Google 的 glTF 展示元件                                                                                           | 一行就能放一個模型                                                                                                   | 一個元件只能放一個模型，做不出多隻魚同時游的場景                 |

**採用 A**。PR c 會新增 `three`（MIT）和開發用的 `@types/three`，開始前再確認一次。

模型壓縮用 `gltf-transform` CLI（MIT），只在整理素材時用 `npx` 執行一次，不加入專案的相依套件。

### 效能與無障礙守則（會寫進設計系統）

- 3D 程式只在首頁載入，其他頁面完全不受影響。
- 畫面像素比上限是 1.5。手機限制在 30fps，桌機 60fps。
- 魚缸最多同時顯示 12 隻魚。超過的魚一樣保存在「我的魚」裡，可以自己選要放哪幾隻進魚缸。
- 分頁被隱藏或切到背景時，暫停繪製。
- 系統開啟「減少動態效果」時，只畫一張靜止的畫面，魚不游動。
- 瀏覽器不支援 WebGL 或載入失敗時，改用一張靜態的水色漸層，首頁功能一樣能用。
- 所有模型壓縮後的總大小控制在 3MB 以內，在 3D 程式之後才延遲載入，不擋住首頁的文字和按鈕。
- canvas 加上 `aria-hidden`，純裝飾，不會被螢幕閱讀器讀出來。魚缸裡有哪些魚，改用文字列在「我的魚」。

### 整頁背景的可讀性

- 魚缸固定在首頁最底層（`position: fixed`）。
- 標題、點數、日曆、影片庫卡片都放在不透明的 surface 卡片上，文字對比沿用現有 tokens，不受水色影響。
- 卡片之間留出空隙，讓魚缸透出來。
- 深色模式和淺色模式都用同一個深海色調。光源和霧的顏色會寫進設計系統，成為新的 token。

## 2. 點數與飼料（兩種分開計算）

### 2a. 點數：只用來買魚

數字集中在 `lib/rewards.ts` 的 `REWARDS`。

| 行為                                 | 點數                               | 說明                               |
| ------------------------------------ | ---------------------------------- | ---------------------------------- |
| 完成當天的**正式**任務（第 1～7 天） | +10                                | 每支影片、每週、每天只算一次       |
| 第 1 天、第 7 天聽寫的正確率加分     | + 正確率 × 10（四捨五入，0～10）   | 鼓勵認真聽寫                       |
| 跟讀平均涵蓋率 ≥ 90%                 | +5                                 | 「我念完了」完成的句子不算在平均裡 |
| 週結算通過                           | +50                                |                                    |
| 週結算沒通過，但完成了這一週         | +20                                | 不懲罰重來一週                     |
| 連續練習（以日曆日計算）             | 從連續第 3 天起，每天 +5（不遞增） | 只要當天完成任一個正式任務就算     |
| 重練                                 | 每支影片每天第一次重練完成 +2      | 鼓勵複習，但避免刷點數             |

- **防止重複領取**：每一筆點數都有唯一 ID，例如 `day:sintel:w1:d3`、`week:sintel:w1`、`streak:2026-10-27`。帳本裡已經有的 ID 不會再加一次，重新整理或重做都不會重複給點。
- **既有進度補發**：獎勵都從紀錄推算（正式進度、往週紀錄 `history`、練習紀錄 `ll-activity:v1`），帳本只發還沒領過的 ID，所以舊進度第一次開啟就會自動補發。已經重來一週的舊週，各天紀錄已清空，只能補發那一週的週結算點數。

### 2b. 飼料：每天完成任務得 1 份，用來餵魚

- **怎麼得到**：每個日曆日，第一次完成任一個**正式**任務時得到 1 份飼料。不論是哪支影片，一天最多 1 份；重練不算。
  - 唯一 ID 是 `feed:2026-10-27`，所以不會重複發。
- **可以累積**：飼料可以存起來，最多存 7 份，存滿後就不再增加。這樣偶爾沒空餵也不會白做。
  - 剛開始會送 1 份，讓第一次就能試著餵魚。
- **餵魚**：每撒一次飼料消耗 1 份。一天可以餵很多次，但日曆只記「這天有餵」。
- **既有進度補發**：已經完成任務的過去日子會補發飼料，但同樣受「最多存 7 份」限制。
- **日曆**：魚飼料圖示代表**那天有餵魚**，不是有練習。

### 2c. 飢餓狀態（溫和、不懲罰）

- 上次餵食之後，超過 1 天沒有餵，也就是今天和上次餵食日相差 2 天以上，魚就會進入「餓了」的狀態：
  - 游得比較慢；
  - 比較常待在缸底。
- 一餵食就立即恢復。
- **魚不會死亡、生病或消失**，也不會因為餓而扣點數。
- 首頁會用一行文字溫和地提示：「魚有點餓了，完成今天的任務就能得到飼料。」文字不只靠動畫傳達狀態。

### 商店價格草案

| 魚             | 價格 | 大約要練多久 |
| -------------- | ---- | ------------ |
| 小丑魚         | 40   | 約 2～3 天   |
| 水蝸牛         | 30   | 約 2 天      |
| 鯊魚（大白鯊） | 200  | 約一週半     |
| 鯨鯊           | 400  | 約三週       |

- **起始魚缸**：一開始就有一隻水蝸牛，讓魚缸不會是空的。
- 同一種魚可以重複購買。
- 點數只能用在商店，不能退款，也不會過期。

- Sketchfab 上有人把**別人的作品重新上傳**，或者授權欄位標錯。例如搜尋結果裡有一個名叫「snail_non-commercial」的模型，授權欄卻標成 CC BY。所以每個素材都要看描述、確認原作者，有疑慮的一律不用。

## 4. 資料與架構

### `lib/`

- **`lib/rewards.ts`**（PR a）：獎勵規則，全部是純函式。`REWARDS` 集中所有數字；`pointRewards`、`feedRewards` 從紀錄推算出帶唯一 ID 的獎勵；`streakPoints` 計算連續天數獎勵。
- **`lib/activity.ts`**（PR a）：每天的練習紀錄（正式任務、重練）。重練不寫進正式進度，所以另外記錄。
- **`lib/wallet.ts`**（PR a）：只新增不修改的帳本，點數（`earned`／`spent`）與飼料（`earned`／`used`）分開。`claim` 只發還沒領過的 ID，飼料最多存 7 份。PR b 加上購買（`spent`）與擁有的魚。
- **`lib/claim-rewards.ts`**（PR a）：讀紀錄、領取、存檔，一次只跑一個，避免同時領取時用到舊帳本。
- **`lib/feeding.ts`**（PR c）：餵食（消耗飼料、記錄餵食日期）、`isHungry(lastFed, today)`，給魚缸和日曆使用。
- **`lib/fish.ts`**（PR b）：魚的型別和驗證，資料放在 `data/fish/`。

### 儲存

- `lib/storage/reward-store.ts` 定義 `RewardStore`；MVP 用 localStorage（`local-reward-store.ts`），key 是 `ll-wallet:v1`、`ll-activity:v1`，之後可以換成 Supabase。

### 發點時機

- 正式任務、週結算、重練完成時，各頁存檔後順便呼叫 `claimRewards`。
- 因為有唯一 ID，就算呼叫很多次也只會給一次。

### 畫面

- **頁首**：顯示「點數 120 · 飼料 2 份」。圖示都用設計系統的 SVG 圖示，不使用 emoji。
- **首頁**：由上到下是標題卡、餵魚卡（剩幾份飼料、「餵魚」按鈕、飢餓提示）、這個月的日曆卡（有餵魚的日子顯示飼料圖示）、影片庫。
- **`/shop`**：每隻魚有預覽、價格、「購買」按鈕。點數不夠時按鈕停用，並說明「還差 N 點數」。
- **`/shop` 的「我的魚」**：可以選擇哪些魚放進魚缸。

## 5. 魚缸的餵魚與互動（第 c 個 PR）

| 動作                       | 魚的反應                                                                             | 開啟「減少動態效果」時                               |
| -------------------------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| **點水面**（有飼料時）     | 從點的位置撒下飼料，飼料緩慢下沉；最近的幾隻魚游過去吃，吃完飼料就消失；記錄今天有餵 | 不播放下沉和游動，直接顯示「已餵食」，並記錄今天有餵 |
| 點水面（沒有飼料時）       | 不撒飼料，顯示「今天完成任務就能得到飼料」                                           | 同左                                                 |
| **點魚**                   | 轉身、吐泡泡，並在旁邊顯示名字（例如「小丑魚」）                                     | 只顯示名字                                           |
| **點玻璃附近**（畫面邊緣） | 附近的魚四散游開                                                                     | 不動                                                 |
| **游標或手指移動**         | 附近的魚好奇地慢慢靠近                                                               | 不動                                                 |

- **無障礙**：只靠點水面餵魚，鍵盤和螢幕閱讀器使用者會做不到。所以首頁的餵魚卡上也有一個「餵魚」按鈕，效果和點水面一樣，飼料從水面中央撒下。
- **退回靜態背景時**（瀏覽器不支援 WebGL 或載入失敗）：一樣可以用按鈕餵魚，日曆照常記錄。
- **點擊判斷**：用 Three.js 的 Raycaster 判斷點到的是魚還是水面；畫面四邊的一定範圍算「玻璃附近」。
- **捲動和點擊**：魚缸是整頁背景，只有點在卡片之間的空白處才會觸發魚缸互動，點到卡片時一律照卡片本身的操作處理。

- 開 PR，等 CI 通過後給你預覽網址，等你說「合併」才合併。

  - 確認 WebGL 失敗時會退回靜態背景。
