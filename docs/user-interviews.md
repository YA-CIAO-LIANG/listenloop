# Beta 使用者訪談

這份文件用來準備 ListenLoop 的 Beta 使用者訪談，內容包括：

- 原則；
- 20 分鐘的腳本；
- 學生、上班族、老師三種版本的問題；
- 紀錄範本；
- 怎麼把訪談結果變成產品決策。

決策記在 `docs/decisions.md` 的 D152。

> **Beta 測試的訪談時機**（D165）：每位 Beta 測試者在加入後第 3 天、第 14 天各一次，問題見 `docs/beta-test-plan.md` 第 5 節；後台「Beta 測試」頁的「訪談」欄會提醒時機。本文的腳本用於還沒用過產品的人。

## 1. 原則：The Mom Test

The Mom Test 出自 Rob Fitzpatrick 的同名書。重點是：**連你媽媽都沒辦法對你說客套話的問題**。人很容易為了禮貌說「這個好棒，我一定會用」，但這種話對產品決策沒有幫助。

| 要問                                                   | 不要問                                                 |
| ------------------------------------------------------ | ------------------------------------------------------ |
| 過去實際發生的事：「上一次準備聽力考試，你做了什麼？」 | 假設的未來：「你會不會用一個每天 15 分鐘的聽力 App？」 |
| 具體的細節：「那次花了多久？用了什麼？」               | 意見與讚美：「你覺得這個點子好嗎？」                   |
| 已經付出的代價：「你為這件事花過錢或時間嗎？」         | 價格假設：「你願意付 149 元嗎？」                      |
| 他們怎麼解決：「後來怎麼處理？」                       | 引導式問題：「聽不清楚是不是很困擾？」                 |

**訪談時的規則**：

1. **不介紹產品**，至少前 15 分鐘不要。一介紹，對方就會開始給你意見，而不是講他自己的事。
2. **多聽少說**：你說話的時間不超過 20%。
3. **追問細節**：對方說「我常常…」，就問「最近一次是什麼時候？那次發生了什麼？」
4. **記原話**，不要記自己的解讀。「我聽 podcast 都聽不懂就關掉了」比「使用者覺得 podcast 太難」有用得多。
5. **讚美不算數**：「聽起來很棒」不是訊號。訊號是對方願意付出代價：時間、介紹別人、付錢、願意下週再聊。
6. **找出「怎樣算成功」**：對方心目中的「聽力變好」長什麼樣子？看美劇不用字幕？考試聽力拿到幾分？開會聽得懂客戶？

## 2. 訪談腳本（約 20 分鐘）

適用於所有對象。第 3 節有三種對象各自的問題，放在「過去的行為」那一段。

### 開場（2 分鐘）

> 謝謝你願意花 20 分鐘跟我聊。我在做一個和英文聽力有關的東西，但今天**不是**要介紹它，而是想了解你平常怎麼學英文、遇過什麼困難。沒有標準答案，講實話對我最有幫助，就算你覺得「我其實沒在練」也很好。
>
> 我可以錄音嗎？錄音只給我自己整理筆記用，不會公開，整理完就刪除。你隨時可以說「這段不要錄」或停止訪談。

- 錄音前一定要取得同意。不同意就只寫筆記。
- 不要說產品名稱，也不要說「我們的 App 可以…」。

### 背景（3 分鐘）

- 「先簡單介紹一下你自己：在讀書或在工作？做什麼的？」
- 「英文在你現在的生活裡，什麼時候會用到？」
- 「最近一次需要聽懂英文是什麼情況？」：要問到具體的一次。

### 過去的行為（10 分鐘）

用第 3 節對應對象的問題。**每個問題都追問到具體的一次**：

- 「最近一次是什麼時候？」
- 「那次你做了什麼？用了什麼工具或資源？」
- 「花了多久？持續多久之後停下來？為什麼停？」
- 「那次之後有什麼改變嗎？你怎麼知道有沒有進步？」

### 痛點與「怎樣算成功」（3 分鐘）

- 「在你剛剛說的這些經驗裡，最讓你挫折的是哪個部分？」
- 「如果半年後你的英文聽力『變好了』，那時候的你會做到什麼現在做不到的事？」：要問到具體的畫面，例如「看 YouTube 上的科技評論不用開字幕」。
- 「為了解決這件事，你花過錢嗎？花了多少？值得嗎？」

### 收尾（2 分鐘）

- 「還有什麼我應該問、但沒有問到的嗎？」
- 「你身邊有沒有人也在練聽力，可以介紹我跟他聊聊？」：願意介紹是一個承諾訊號。
- 「我們之後有一個測試版，你願意試用兩週，然後再跟我聊 15 分鐘嗎？」：願意約下一次，比說「好棒」可靠得多。
- 謝謝對方。說好的小禮物（例如飲料券）要當場給。

## 3. 三種對象的問題

每種約 10 題，不需要全部問完。**優先問「上一次」的題目**。各題後面標了容易犯的錯誤，提醒自己不要那樣問。

### 3a. 學生（高中、大學、留學生）

1. 「上一次準備英文聽力考試（學測、英檢、多益、雅思、托福、學校考試）是什麼時候？那次你怎麼準備？」
   - 追問：每天多久？用了哪些書、App、YouTube 頻道？準備了幾週？
2. 「考出來的結果，和你預期的差多少？你覺得差在哪裡？」
3. 「你上一次『聽不懂』英文是什麼情況？」：上課、影片、外國同學、考試都可以。
   - 追問：那次你怎麼辦？重聽？開字幕？放棄？
4. 「你現在手機裡有哪些學英文的 App？最近一次打開是什麼時候？」
   - 追問：下載後用了多久？為什麼不用了？
5. 「你有沒有為了英文聽力花過錢？補習、課程、App 訂閱？大概多少？」
6. 「有沒有哪一次你覺得『我的聽力真的進步了』？那時候發生了什麼？」
7. （留學生）「出國前和剛到的第一個月，聽力上最困難的是什麼？最近一次聽不懂是什麼情境？」
8. 「平常看英文影片會開字幕嗎？開中文還是英文？上一次不開字幕看是什麼時候？」
9. 「你通常什麼時間練英文？在哪裡？用手機還是電腦？」
10. 「如果下週要考聽力，你今天晚上會做什麼？」

**避免**：

- 「你覺得每天練 7 天的循環有沒有用？」：這是假設問題，而且在推銷。
- 「學生方案 90 元你會買嗎？」：問價格假設，得到的是客套話。

### 3b. 上班族

1. 「工作上最近一次需要聽懂英文是什麼情況？」例如會議、客戶電話、教育訓練影片、出差。
   - 追問：那次聽懂了多少？漏掉的部分後來怎麼補？
2. 「有沒有因為英文聽不清楚，造成工作上的問題或尷尬？發生了什麼？」
3. 「你最近一次為了英文主動做了什麼？」例如上課、看影片、聽 podcast、背單字。
   - 追問：持續多久？為什麼停下來？
4. 「一週裡面，你實際能拿出來練英文的時間有多少？通常在哪個時段？」例如通勤、午休、睡前。
5. 「你為英文花過多少錢？公司有補助嗎？補助怎麼申請？」
6. 「你有用過哪些英文 App 或課程？最後留下來的是哪一個？為什麼？」
7. 「工作上的英文，跟考試或課本的英文，你覺得最大的差別是什麼？舉一個例子。」
8. 「上一次聽 podcast、YouTube 或英文影集，是什麼內容？聽懂多少？」
9. 「主管或公司有沒有要求英文能力（多益分數、升遷條件）？上次被要求是什麼時候？」
10. 「如果英文聽力變好，你工作上最想做到的一件事是什麼？」

**避免**：

- 「通勤時用 App 練聽力是不是很方便？」：這是引導式問題。
- 「你會希望有商務英文的教材嗎？」：對方幾乎一定說「會」，但沒有參考價值。

### 3c. 老師（英文老師、補習班老師）

1. 「你上一次在課堂上做聽力練習是怎麼進行的？用了什麼素材？」
   - 追問：素材從哪裡來？準備花了多久？
2. 「學生的聽力作業，你上一次是怎麼出、怎麼收、怎麼批改的？」
3. 「你怎麼知道一個學生的聽力有沒有進步？上一次看到明顯進步的學生，他做了什麼？」
4. 「準備聽力教材時，最花時間的是哪一步？」例如找素材、對時間點、寫講義、出題。
5. 「你用過哪些數位工具（Google Classroom、Quizlet、Kahoot、YouTube…）？最近一次用是什麼時候？哪個留下來了？」
6. 「學生回家練習的狀況，你上一次是怎麼掌握的？」
7. 「學校或補習班有沒有為數位工具付費？上次購買是誰決定、怎麼決定的？」
8. 「上一次有學生跟你說『聽不懂』，你怎麼處理？」
9. 「版權上，你上課用的影片或音檔通常怎麼取得？有沒有遇過不能用的情況？」
10. 「如果一學期後全班的聽力變好，你會用什麼證明？」例如考試分數、課堂表現、學生自己說。

**避免**：

- 「班級功能可以看到每個學生的進度，你會想用嗎？」：在推銷功能。
- 「你們學校會買嗎？」：要問的是上一次的採購經驗，不是假設。

## 4. 訪談紀錄範本

每場訪談一份，存在 `docs/interviews/` 底下，檔名格式是 `YYYY-MM-DD-代號.md`。

- **不寫真實姓名、學校或公司名稱**，只用代號（S01、W01、T01）。
- 錄音整理完就刪除。

```markdown
# 訪談 S01（學生）

- 日期：2026-11-20；時長：22 分鐘；方式：視訊；訪談者：Joe
- 背景：大二，資管系，準備多益，目標 800
- 錄音：已同意，整理後刪除（2026-11-21 已刪）

## 原話摘錄（逐字）

- 「我買過 OOO 一年，用了兩週就沒開了，因為每天都在提醒我，很煩。」
- 「我聽美劇其實聽得懂劇情，但要我寫下來他講什麼，我寫不出來。」

## 過去的行為

| 什麼時候 | 做了什麼 | 用什麼 | 持續多久 | 為什麼停 |
| -------- | -------- | ------ | -------- | -------- |
| 2026-09  | 多益模考 | 書＋CD | 3 週     | 開學太忙 |

## 痛點（依對方的強度排序）

1. 聽得懂大意，但抓不到每個字（「寫不出來」）：強
2. App 的提醒讓人有壓力：中

## 怎樣算成功（對方的話）

- 「多益聽力 400 以上」、「看 YouTube 科技評論不用開字幕」

## 已經付出的代價

- 錢：OOO App 年費約 2,000 元；補習班 0
- 時間：每天通勤 30 分鐘聽 podcast（持續中）

## 承諾訊號

- [x] 願意試用 Beta 兩週
- [ ] 介紹其他人（說會問同學，沒有給名字）
- [ ] 願意付費（沒有問，不要問假設的價格）

## 我的解讀（和原話分開寫）

- 「確定感」的痛點吻合；提醒要可以關掉
```

## 5. 從訪談到產品決策

### 整理（每場訪談後 24 小時內）

1. 照範本寫好紀錄，原話和解讀分開寫。
2. 把每個痛點寫成一張卡片：「誰、在什麼情況、遇到什麼問題、現在怎麼解決」。

### 彙整（每完成 5 場檢討一次）

1. **痛點矩陣**：橫軸是提到的人數（頻率），縱軸是強度（有沒有為它付出代價：錢、時間、換過工具）。
   - **右上**（很多人提到，而且有付出代價）：優先處理。
   - **左上**（少數人提到，但很痛）：記下來，看是不是某一類對象特有的問題。
   - **下方**（沒有付出代價）：通常是客套話，先不處理。
2. **門檻**：**至少 3 個人**在**過去的行為**中提到同一個痛點，才列為產品候選。只出現在「我覺得」「應該會」的不算。
3. **成功的定義**：把每個人說的「怎樣算成功」分類，例如考試分數、不開字幕、工作溝通。這會決定首頁怎麼呈現「看得見的進步」，以及學習分析要顯示什麼。
4. **分對象看**：學生、上班族、老師的痛點可能完全不同。只有一類對象有的痛點，要問自己這是不是我們的目標使用者（目前是台灣學生，見 CLAUDE.md）。

### 決策

1. 每個候選寫成一筆 `docs/decisions.md` 的記錄，內容包括：
   - 哪些訪談提到（代號）；
   - 原話；
   - 頻率與強度；
   - 要做什麼、不做什麼。
2. 排進 `docs/roadmap.md`。對使用者影響大、做起來小的優先。
3. **驗證**：做出來之後，回頭找提到這個痛點的受訪者試用，問的是「上次用的時候發生了什麼」，而不是「你喜歡嗎」。
4. 和 Clarity（D148）與學習分析的數據互相對照：訪談告訴你**為什麼**，數據告訴你**有多少人**。

### 常見的陷阱

- **確認偏誤**：只記得支持自己想法的話。對策是寫逐字原話，而且每 5 場由另一個人讀一遍紀錄。
- **被讚美帶走**：「好棒，我一定會用」不是證據。
- **問了假設問題**：發現的時候，把話題拉回「上一次……」。
- **太早介紹產品**：一旦介紹，後面的回答都會受影響，那一場的「過去的行為」要特別標註。
