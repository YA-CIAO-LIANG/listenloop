### 2. 第〇項的原因與修正

- **你看到的那次**：正式站 `api_calls` 裡 11/9 下午那 4 次 `revise` **都是成功**（沒有錯誤、沒有 HTTP 錯誤），輸出都只有 123 tokens，等於把 7 句原文照抄回來。
- **原因**：舊提示詞要模型「只改需要的部分」，而且「指令不安全或和內容無關時原樣回傳」；模型把「恐怖風」當成不安全或不需要改，照抄回來，而且沒有辦法說明為什麼。程式又把「句子都一樣」當成成功，顯示「0 句變動」。內容過濾也和一般失敗顯示同一句話。
- **修正**：
  - 模型回傳狀態（已修改／不需修改／拒絕）與原因；提示詞明確支援整體風格與語氣（恐怖、幽默、正式、口語、童話、新聞），可以增減句數；恐怖風改寫成輕微懸疑，不涉及血腥暴力。
  - 伺服器再把關：句子完全沒變一律說明「沒有改動」，**不再出現「0 句變動」**。
  - 三種訊息：「修改失敗，請稍後再試」、「這個指令的內容無法產生，請換個說法」（附模型的建議）、「AI 判斷不需要修改：原因」。
  - **先預覽再套用**：修改前／修改後對照，改過的句子標「改過」；按「套用」才翻譯並寫入，可以「復原上一步」。標題不會被改。
  - 用量頁每次呼叫都記錄結果與 HTTP 狀態，例如「成功（HTTP 200 · changed 8/8）」（新增 `api_calls.outcome` 欄位，只新增，已套用）。
- **實際 API 花費**：2 次真實呼叫（核准上限 2 次、US$0.02），**885 輸入／326 輸出 tokens，US$0.000873**。一次用舊提示詞、一次用新提示詞，同一段 7 句文字加「改成恐怖風」：新提示詞改成 8 句懸疑風格。舊提示詞用我的文字這次有改，所以舊問題不是每次都會發生；你那段文字連續 4 次都被照抄。結果存成 fixture，之後只重播。
- 其他各項都沒有呼叫真實 API；聲音 0 字元。

### 4. YouTube 環境變數與設定步驟

只有一個：**`YOUTUBE_API_KEY`**，放在 Vercel 的 **Production**（要在預覽網址測試，也勾 **Preview**）。不需要信用卡，用的是免費配額（每天 10,000 單位，每次查詢影片 1 單位）。

1. 打開 Google Cloud Console（<https://console.cloud.google.com/>），選現有的專案（例如放 Cloud Text-to-Speech 的那個）或新建一個。
2. 「API 和服務」→「程式庫」→ 搜尋「YouTube Data API v3」→「啟用」。
3. 「API 和服務」→「憑證」→「建立憑證」→「API 金鑰」，複製金鑰。
4. 點這個金鑰 →「API 限制」選「限制金鑰」→ 只勾「YouTube Data API v3」→ 儲存（應用程式限制可以先不設；網站是從伺服器呼叫）。
5. Vercel → listenloop 專案 → Settings → Environment Variables → 新增 `YOUTUBE_API_KEY`，值貼上金鑰，環境勾 Production（需要的話加 Preview）→ Save。
6. Deployments → 最新的 Production → Redeploy。
7. 正式站用管理員登入 → 後台「API 用量」→ 設定診斷的 YouTube 一項打勾 →「測試連線（免費）」的 YouTube Data API 顯示「連線成功」。
8. 之後 Plus 以上方案與管理員在「建立教材 → YouTube 連結」就能使用；免費使用者看到升級說明（記錄在後台「付費意願」）。
