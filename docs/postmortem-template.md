# 事後檢討：〈事件名稱〉（範本，D157）

> 複製這份到 `docs/postmortems/YYYY-MM-DD-簡短名稱.md` 再填寫。**對事不對人**：目的是讓同樣的事不再發生，不是追究誰的錯。SEV1、SEV2 在一週內寫完。

## 摘要

- **嚴重程度**：SEV1／SEV2／SEV3（定義見 `docs/incident-runbook.md` 第 0 節）
- **影響時間**：YYYY-MM-DD HH:MM ～ HH:MM（台灣時間），共 ○ 分鐘
- **影響範圍**：哪些功能、大約多少使用者、有沒有資料遺失或外洩
- **一句話說明**：發生了什麼、為什麼

## 時間軸（台灣時間）

| 時間  | 事件                                         |
| ----- | -------------------------------------------- |
| HH:MM | 問題開始（例如部署了某個版本）               |
| HH:MM | 發現（是誰、透過什麼發現：通知、使用者回報） |
| HH:MM | 開始處理                                     |
| HH:MM | 止血（用了哪個開關或回滾）                   |
| HH:MM | 發布公告                                     |
| HH:MM | 完全恢復                                     |

## 根本原因

用「五個為什麼」往下追，直到找到可以改的地方：

1. 為什麼網站壞了？→
2. 為什麼會這樣？→
3. 為什麼測試沒有抓到？→
4. 為什麼監控沒有更早發現？→
5. 為什麼？→
