# 資料庫 migration 的回復方式（D157）

每個 migration 都要能回復。這份文件列出每個既有 migration 的反向操作；**2026-11-22 之後新增的 migration，回復方式寫在檔尾的 `-- Rollback:` 區塊**，由 `tests/migration-rollback.test.ts` 檢查。

## 原則

1. **先回滾程式，不急著回滾資料庫。** 我們的 migration 幾乎都是「只新增」：新增資料表、欄位、函式。舊版程式不會用到新的東西，所以 Vercel 回到上一版後，新的資料表留著也沒關係（`docs/deploy-rollback.md`）。
2. **真的要回復資料庫時**：
   1. 先備份（`docs/backup.md`），確認這次的備份解得開；
   2. 在 Supabase 的 SQL Editor 執行反向操作，一次一個 migration，從最新的往回；
   3. 刪除 `supabase_migrations.schema_migrations` 裡那個版本的紀錄，`npm run db:push` 才不會以為它還在：
      `delete from supabase_migrations.schema_migrations where version = '<檔名開頭的 14 位數字>';`
   4. 執行 `npm run rls:check`，確認權限規則仍然正確。
3. **刪除或修改資料的 migration 不能用反向操作回復**，只能從備份還原（表中標「只能從備份還原」）。
4. `drop table` 會連同裡面的資料一起刪除；刪 bucket 會連同檔案一起刪除。執行前先確認有備份。
5. 「—」表示這個 migration 只改了 policy、view、權限或函式內容：回復時，把相關的定義換回前一個 migration 的版本（看檔案內容）。
